## 2. 実装を調べて確認した事実（仕様と区別）

調査時点の `history-master` の `index.html` は約5204行で、HTML・CSS・JavaScriptを含む。現在の学習コードは選択肢を前提とする。

- `DB_NAME="history-master-sample-v1"`、`DB_VERSION=10`、17ストア。新アプリではこのDB名を絶対に使わない。
- `BACKUP_FORMAT="history-master-backup"`、`BACKUP_VERSION=10`。旧1〜10形式への互換処理は歴史マスター固有。
- `answers`、`sessions`、`studySets` の検証には選択肢インデックスの `selected` と `optionOrder` が含まれる。数字回答型への変更は保存・復元も含む。
- 基本重み `questionWeight`：未回答5、回答ありは `1+4×[1−(correct+1)/(attempts+2)]`。段別相当の `pickQuestion` は未習得10倍／習得済み1倍に加え、直近3問を原則回避。ジャンル別のセット抽選は未習得10倍を使用しない。
- 苦手候補は過去に誤答したことがあり、現在習得済みでない問題。
- カードは現在、10時代の `ERAS` と50問以上の条件を前提とする。9段＋完全制覇に合わせて判定・表示・復元検証を修正する必要あり。
- `saveAnswer` は学習進捗と回答イベント、コイン、カード、セッションを同じIndexedDBトランザクションで保存する。二重付与防止を壊さない。
- クレーンとランナーの支払い・保存は親アプリ側。ランナーは `runner/` 以下の iframe ゲームを使う。
- `index.html` とランナー用主要JSで `localStorage`/`sessionStorage` の直接使用は調査時未検出（全ファイルの変更時に再確認）。IndexedDB・アプリルート・JSON形式・ファイル名に歴史識別子あり。
- 参照元の未マージPR（調査時：#144、#30、#1）は移植対象へ自動で含めない。元の古い設計文書とコードの差がある場合はコードを優先して事実確認。

## 3. 新アプリ固有の保存設計（PR-1〜PR-2で要確定）

**分離の重要な原則：GitHub Pagesのサブパスが異なっても、同じオリジンならIndexedDBのデータベース名が一致すると共有される。**

- 固有DB名の推奨：`kakezan-master-v1`。固有のバックアップ形式の推奨：`kakezan-master-backup`。値はPR-1のレビュー時に確定する。
- `history.state` のアプリ名、バックアップファイル名、各種JSON識別子、キャッシュ・設定のキーを検索し、移植元の値を誤って使わない。
- 新アプリ版、DBスキーマ版、バックアップ版は別の数字として管理する。DB名を途中で変えてデータを孤立させない。
- 新しいバックアップで`student`と`test`の両プロフィール、17ストア相当のゲーム記録、カード全10枚、数値解答、途中セッションが整合すること。
- 数値回答の記録形式は、既存 `answers` と `progress` の意味（正誤、時刻、2連続習得、通算正解回数）を保持しながら拡張。履歴を勝手に消さない。
- 保存データや児童情報、実バックアップを公開リポジトリへコミットしない。試験には作り物の記録のみを使う。

## 6. 開発と受入の運用

1. GitHub新リポジトリ main を基本とし、各PRは開始前に最新mainと版番号を確認する。
2. 関連Issueの有無を確認し、必要ならユーザーの承認範囲で作成する。
3. 変更範囲、互換性、テスト方法を確定してからCodexに実装を依頼する。
4. Codexは作業ブランチでテスト後、**ドラフトPRを作成して停止**する。
5. ChatGPTが差分とテスト・CIをレビュー、ユーザーがマージを判断。
6. mainへの直接push、PRの勝手なマージ、タグ、公開設定、既存データの削除はしない。

**現時点の検査結果**：GitHubソースの読み取り調査のみ実施。かけざんマスターでの自動テスト、iPhone/iPad Safari実機テスト、リポジトリへのプログラム移植は未実施。


## 7. PR-3 実装判断（2026-11-23）

- 基準main `b81cbac7a108bec259ee7493ab046a53a9fd517c`、v0.2.0からv0.3.0。具体的な結果は [PR-3報告](PR3_REPORT.md) を参照。上記の調査記録・未実施表記は各段階時点のもの。
- 理解度は従来どおり `(習得済み + 0.5 × 1回連続正解) / 問題数 × 100`。各段9、全体81を母数にし、画面は整数切り捨て。9軸の読み上げラベルもプロフィールごとの値で更新。
- カードIDは `T01`〜`T09` と `ALL81`。旧 `E01`〜`E10` と同じawardsストアに共存し、`profile:ID`をキーとする。現在の9問／81問の全習得を検査し、回答・コイン・セッションと同一トランザクションでadd。既得カードの日時は更新しない。追加コインなし。
- 起動／復元時の未授与補完もprogressとawardsを単一readwriteトランザクションで扱う。補完日時は条件を満たす問題の最終回答日時の最大値。既存の回答日時を含む旧記録は変更せず、未授与カードのみ追加する。
- DB名とバックアップ形式を固定したまま版を12に更新。新カード非対応の旧タブをversionchangeで閉じ、旧版が新カードを含むデータを旧検証条件で扱わないようにする。ストアは17個で変更なし。v10/v11バックアップを継続受入、書出しはv12。直接ダウングレードは不可。
- 最大awards件数は40（旧10＋新10、プロフィール2種類）。旧カードは50問以上、新段カードは9問ちょうど、完全制覇は81問ちょうどとして検証。現時点の未習得を理由に既得カードの復元を拒否しない。
- 保護者一覧は固定81問IDに一致するanswersのみ、全期間を集計。正答率は正解数／回答数、表示は整数四捨五入。並べ替えは丸める前の比率、同率はID順、未回答は昇降どちらも最後。○×履歴は展開時に全件描画し、記録は切り捨てない。
- カードはテキスト・チェック等の仮表示。歴史画像は使用しない。10種類の異なるキャラクターの図案・名称・モチーフはユーザーとの意匠確定後に別PRで制作する。
- ブラウザ自動試験は実機Safari確認とは区別。PR-1からのクレーン位置計測、縦横・Split View・文字拡大・VoiceOverと実機操作はPR-4の残件として追跡。
