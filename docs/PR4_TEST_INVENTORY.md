## 移植の優先順位と影響

1. Mの管理・版表示・バックアップ・残高を、旧問題管理UIから独立した九九fixtureへ移す。APIの旧名だけを置換しても選択肢型セッションは数値型にならない。正本は固定81問、保存済み旧レコードは保持する。
2. Hの競合・中断／再開・遅延／abortのシナリオを、`MULT:Txx:yy`、number回答、mix/weakへ移植する。現行の基本経路はmultiplication／positive_coin_reward／progress_cardsで検証済みだが、旧群の全異常系を代替したとはしない。
3. Oは編集成功を現在の製品要件に戻さない。公開UIの編集不可・非表示検査と、旧レコードのバックアップ保持・不正形式拒否へ観点を分割する。関数の削除や旧データの削除は今回行わない。
4. 旧3/7景品の保存プレイ、旧runner stageVersionはデータ互換として現行でも有効。「旧」という名前だけで廃止扱いにしない。現行17ストアの整合fixtureとv12の期待値に修正した試験は総合報告へ記載する。

仕様変更が必要な新機能は含めない。上記の追加移植は提案であり、今回すべて完了したとは報告しない。
